# 화면 정의서

> 요약: 화면 목록·ID, 화면 흐름, 화면별 구성 요소·데이터·동작·상태(로딩/빈/오류/권한 없음)·문구와 연결 기능 ID를 정의한 화면 정의서를 만든다.
> 산출물: crewgenai-output/docs/06-screen-definition.md

## 언제 쓰나

- 기능 명세(05)가 나온 뒤 화면 설계·디자인을 시작할 때
- 프런트엔드 개발자가 화면별 데이터·동작·상태를 한 문서로 확인해야 할 때
- 로딩·빈 상태·오류·권한 없음 같은 예외 화면을 빠짐없이 정해야 할 때
- 화면 흐름 검토(14 화면·전체 흐름) 전에 기준 문서가 필요할 때

## 운영 탭에 붙여넣을 지시문

```text
목표: {{제품명}}의 화면 정의서를 작성한다. 결과는 crewgenai-output/docs/06-screen-definition.md 한 파일이다.

담당 배정: 00 총괄이 계획, 14 화면·전체 흐름이 화면 목록·흐름과 초안, 07 승인·권한 검토가 권한 없음 상태, 13 이메일 알림이 알림 연결 화면, 15 통합 품질·결과물이 형식 점검을 맡는다.

작성 규칙:

- 화면 흐름은 Mermaid flowchart로 그리고 화살표마다 이동 조건(버튼·결과)을 적는다.

- 권한 없음 상태는 서버 응답을 기준으로 정의한다. 화면에서 버튼을 숨기는 것만으로 권한을 처리했다고 쓰지 않는다.
- 문구는 직접 확정하지 않고 CT-xxx로 참조하거나 "CT 후보"로 표시한다.
- 근거 없는 데이터 항목·수치·디자인 결정을 지어내지 않는다. "확인 필요"로 둔다.
완료 기준:
- 9개 섹션이 모두 있다. 05 문서의 화면이 필요한 FN이 6절에서 모두 SCR에 연결되거나 미반영 사유가 있다.
- 모든 SCR에 다섯 가지 상태(정상/로딩/빈/오류/권한 없음)가 정의되어 있다. 해당 없으면 사유를 적는다.
결과 파일 경로, SCR 수, 미연결 FN 목록을 마지막 보고에 적는다.
```

## 문서 구성(산출물 목차)

1. 문서 정보 — 제품명, 작성일, 버전, 참고 문서(04·05) 버전, 대상 플랫폼(웹/데스크톱/모바일)
2. 화면 목록 — 표: `SCR ID | 화면명 | 목적 | 진입 경로 | 접근 역할 | 연결 FN | 상태(확정/초안/제안)`
3. 화면 흐름 — Mermaid flowchart(노드는 SCR ID, 화살표에 이동 조건) + 흐름 설명
4. 화면 상세 — 화면별 하위 절, 다음 항목 포함
   - 목적, 진입 경로, 접근 권한, 연결 FN
   - 구성 요소 표: `요소 ID | 종류(버튼·입력·표·목록 등) | 라벨(CT-xxx) | 필수 | 비고`
   - 표시 데이터 표: `항목 | 데이터 출처(API·저장소) | 형식 | 정렬·필터 | 비고`
   - 사용자 동작 표: `동작 | 트리거 | 호출 FN | 성공 시 | 실패 시`
   - 상태 표: `상태(정상/로딩/빈/오류/권한 없음) | 표시 조건 | 화면 표시 | 문구(CT-xxx) | 다음 동작`
5. 공통 요소 — 상단 메뉴, 알림, 확인 대화상자, 오류 표시 방식 등 여러 화면 공통 규칙
6. 기능 반영 대조 — 표: `FN ID | 연결 SCR | 반영 상태(반영/부분/미반영) | 미반영 사유`
7. 근거 목록 — 표: `번호 | 파일경로:줄번호 | 내용 요약`
8. 사용자 결정 필요 항목 — 표: `번호 | 결정할 내용 | 선택지 | 영향 | 결정 기한`
9. 확인 필요 항목 — 표: `번호 | 확인할 내용 | 확인 방법 | 관련 SCR`

## 작성 규칙

- 근거: 화면마다 연결 `FN-xxx`를, 세부 항목마다 `(파일경로:줄번호)` 또는 "확인 필요"를 단다.
- ID 체계: 화면 `SCR-001`, 화면 내 요소 `SCR-001-E01`. 문구는 `CT-xxx`, 기능은 `FN-xxx`를 그대로 인용한다.
- 상태 정의: 다섯 가지 상태를 모두 적고, 해당 없으면 "해당 없음(사유)"로 쓴다.
- 권한: 접근 역할은 04·05 문서의 역할명과 같게 쓰고, 권한 없음 상태는 서버 거부 응답에 대한 화면 처리로 정의한다.
- 숫자 단위: 목록 페이지 크기는 건, 제한 시간은 초, 파일 크기는 MB로 쓴다.
- 디자인 결정(색·배치·글꼴)은 근거가 없으면 "(제안)"으로 표시한다.
