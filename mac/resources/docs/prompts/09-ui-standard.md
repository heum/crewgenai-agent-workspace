# 화면 기준 문서

> 요약: 버튼·간격·목록·배지·작은 화면 같은 화면 모양의 기준을 [확정](사용자가 정함)·[현재](지금 코드 값)·[제안](작성자 안)으로 나눠 적어, 화면 작업마다 같은 기준을 따르게 한다.
> 산출물: docs/UI_STANDARD.md

## 언제 쓰나

- 화면이 있는 제품에서 첫 화면 작업을 시작할 때(지금 코드의 값으로 초안을 만든다)
- "버튼을 예쁘게"처럼 같은 화면 피드백이 여러 사이클에 걸쳐 되풀이될 때
- 직원마다 버튼 단계·간격·배지 색을 다르게 만들어 화면이 들쭉날쭉할 때
- 사용자 피드백을 다음 화면 작업에도 그대로 이어지게 고정하고 싶을 때

## 운영 탭에 붙여넣을 지시문

```text
목표: {{제품명}}의 화면 기준 문서를 작성한다. 결과는 프런트엔드 저장소의 docs/UI_STANDARD.md 한 파일이다.
읽을 자료: 지금 화면 코드(공통 스타일·디자인 토큰·공통 버튼/목록/배지 컴포넌트), {{화면 정의서 경로(있으면)}}, {{사용자 화면 피드백 기록(있으면)}}.
담당 배정: 00 총괄이 계획, 프런트엔드 담당이 지금 코드의 값을 읽어 초안, 검토 담당이 코드 값과 문서가 맞는지 대조한다.
필수 섹션(이 순서): 1 값은 토큰으로만, 2 버튼, 3 목록과 표, 4 상태 표시, 5 작은 화면, 6 화면 작업 방법, 7 아직 정하지 않은 것.
작성 규칙:
- 항목마다 [확정](사용자가 정함)·[현재](지금 코드에 있는 값)·[제안](작성자 안) 중 하나를 붙인다. 사용자가 정하지 않은 것을 [확정]으로 쓰지 않는다.
- [현재]는 코드에서 찾은 값과 그 위치(파일 경로)를 함께 적는다. 찾지 못했으면 "확인 필요"로 둔다.
- 기준은 눈으로 셀 수 있게 쓴다(예: "한 영역에 주 버튼은 하나", "버튼 높이는 2단계"). "예쁘게·깔끔하게" 같은 말은 기준으로 쓰지 않는다.
- 사용자 피드백을 반영한 항목은 [확정]으로 바꾸고 어느 피드백(날짜·사이클)인지 적는다.
완료 기준:
- 7개 섹션이 모두 있고, 모든 항목에 [확정]·[현재]·[제안] 표시가 있다.
- [현재] 항목은 모두 코드 위치가 있다.
결과 파일 경로와 [확정]·[현재]·[제안] 항목 수를 마지막 보고에 적는다.
```

## 문서 구성(산출물 목차)

1. 값은 토큰으로만 — 색·간격·글자 크기·둥글기·그림자는 정해 둔 토큰 이름으로만 쓴다(직접 값 금지). 토큰 목록과 쓰는 곳.
2. 버튼 — 단계(주·보조·텍스트·위험), 높이·여백 단계, 한 영역에 주 버튼은 하나, 아이콘 버튼의 이름표, 누를 수 없는 상태.
3. 목록과 표 — 줄 높이, 한 줄에 보이는 정보 순서, 정렬, 비었을 때·불러오는 중·오류일 때 모습, 많을 때 나누는 방법.
4. 상태 표시 — 배지 색마다 뜻(예: 초록=완료, 노랑=확인 중, 빨강=막힘)과 글자, 같은 뜻에 다른 색을 쓰지 않기.
5. 작은 화면 — 기준 폭(예: 375px), 옆으로 넘치지 않기, 버튼이 줄바꿈될 때 순서, 숨기는 정보.
6. 화면 작업 방법 — 이 문서를 먼저 읽기, 맞는 디자인 스킬 부르기, 전후 화면 사진(PC·모바일 같은 폭·같은 데이터), 새로 정한 모양은 [제안]으로 더하기, 반영한 피드백은 [확정]으로 고치기.
7. 아직 정하지 않은 것 — 사용자가 정해야 할 모양 결정 목록(무엇을, 선택지).

## 작성 규칙

- 공개 저장소에 올릴 수 있는 일반 값만 쓴다. 고객 원문·비밀값·내부 주소를 넣지 않는다.
- 한 항목은 한 줄 기준 + 표시([확정]·[현재]·[제안]) + 근거(피드백·코드 위치)로 쓴다.
- 문서와 코드가 다르면 문서를 고치지 말고 7절에 "문서·코드 불일치"로 올려 사용자가 정하게 한다(어느 쪽이 맞는지 추측하지 않는다).

## 검토 기준(Codex·Claude 재검토용 체크리스트)

- [ ] 7개 섹션이 순서대로 있다.
- [ ] 모든 항목에 [확정]·[현재]·[제안] 중 하나가 있고, [확정]에는 어느 사용자 피드백인지 있다.
- [ ] [현재] 항목의 값이 적힌 코드 위치의 실제 값과 같다.
- [ ] 기준이 눈으로 셀 수 있게 쓰여 있다("예쁘게" 같은 말이 기준으로 쓰이지 않았다).
- [ ] 상태 배지의 색과 뜻이 겹치지 않는다.
- [ ] 비밀값·고객 원문·내부 주소가 없다.

## Claude에 바로 붙여넣는 전체 프롬프트

```text
너는 이 제품의 화면 기준 문서를 만드는 프런트엔드 담당이다. 지금 화면 코드를 읽고 docs/UI_STANDARD.md를 만든다.
섹션: 1 값은 토큰으로만 / 2 버튼 / 3 목록과 표 / 4 상태 표시 / 5 작은 화면 / 6 화면 작업 방법 / 7 아직 정하지 않은 것.
항목마다 [확정](사용자가 정함)·[현재](지금 코드 값과 그 위치)·[제안](내 안)을 붙인다. 사용자가 정하지 않은 것을 [확정]으로 쓰지 않는다.
기준은 눈으로 셀 수 있게 쓴다. "예쁘게" 같은 말은 기준이 아니다. 문서와 코드가 다르면 7절에 불일치로 올린다.
마지막에 [확정]·[현재]·[제안] 항목 수와 확인 필요한 곳을 보고한다.
```
