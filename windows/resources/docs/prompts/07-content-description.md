# 콘텐츠 설명서

> 요약: 화면 문구·안내·알림 메시지 원칙, 데이터·콘텐츠 출처와 갱신 주기, 톤·용어집, 금지 표현을 정의한 콘텐츠 설명서를 만든다.
> 산출물: crewgenai-output/docs/07-content-description.md

## 언제 쓰나

- 화면 정의서(06)의 문구 자리(`CT-xxx`, "CT 후보")를 채울 때
- 화면·이메일 알림·오류 메시지의 말투와 용어를 통일해야 할 때
- 서비스에 표시하는 외부 데이터·콘텐츠의 출처와 갱신 주기를 정해야 할 때
- 과장·보장 표현 등 쓰면 안 되는 문구를 미리 정할 때

## 문서 구성(산출물 목차)

1. 문서 정보 — 제품명, 작성일, 버전, 참고 문서(03·05·06) 버전
2. 문구 원칙 — 짧고 구체적으로, 사용자 행동 중심, 원인과 다음 행동 제시 등 원칙과 예시
3. 톤과 말투 — 표: `상황(안내·성공·경고·오류·확인) | 말투 | 예시 | 피할 말투`
4. 용어집 — 표: `용어 | 정의 | 사용 예 | 쓰지 않는 유사어 | 출처`
5. 금지 표현 — 표: `금지 표현 | 이유 | 대체 표현`
6. 화면 문구 목록 — 표: `CT ID | 사용 위치(SCR-xxx/요소 ID) | 종류(제목·라벨·버튼·도움말·빈 상태·오류) | 문구 | 변수 | 표시 조건 | 관련 FN | 상태`
7. 안내·알림 메시지 목록 — 표: `CT ID | 채널(화면 알림·이메일 등) | 발송 조건 | 수신 대상 | 제목 | 본문 요지 | 변수 | 관련 FN | 상태`
8. 데이터·콘텐츠 출처와 갱신 주기 — 표: `콘텐츠 | 출처 | 수집 방식 | 갱신 주기 | 이용 조건·제한 | 화면 표시 방식(출처 표기 포함) | 근거`
9. 근거 목록 — 표: `번호 | 파일경로:줄번호 | 내용 요약`
10. 사용자 결정 필요 항목 — 표: `번호 | 결정할 내용 | 선택지 | 영향 | 결정 기한`
11. 확인 필요 항목 — 표: `번호 | 확인할 내용 | 확인 방법 | 관련 CT`

## 작성 규칙

- 근거: 용어 정의, 데이터 출처, 금지 사유에 `(파일경로:줄번호)` 또는 "확인 필요"를 단다.
- ID 체계: 문구 `CT-001`. 화면 `SCR-xxx`, 기능 `FN-xxx`, 요구 `REQ-xxx`를 그대로 인용한다.
- 상태 값: `확정`/`초안`/`제안` 중 하나만 쓴다.
- 변수: `{{변수명}}` 형식으로 쓰고, 변수 값이 비었을 때 표시할 내용을 적는다.
- 숫자 단위: 날짜는 `YYYY-MM-DD`, 시간은 24시간제, 금액은 원(KRW)과 천 단위 쉼표를 쓴다.
- 용어: 4절 용어집에 오른 용어만 쓰고, 새 용어가 생기면 먼저 용어집에 추가한다.
- 오류 문구에 내부 코드·경로·비밀값·개인정보를 넣지 않는다.
