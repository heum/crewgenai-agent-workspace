# CREWGENAI 개발팀 관리 — 사용법

검토본 2026-11-10 · macOS(Apple Silicon) · 사용자 한 명이 자신의 Mac에서 AI 팀을 운영하는 앱

> 아래 예시 화면은 시험용 **모의 실행**으로 만들었다(화면 왼쪽 아래에 "모의 실행 모드" 표시). 지시문에 보이는 `[[mock:…]]`는 모의 CLI의 동작을 정하는 시험 표식이며, 실제 사용 때는 쓰지 않는다. 실제 Claude·Codex로 진행한 화면은 **검증 결과** 탭에 있다.

## 화면 구성 — 왼쪽 목록 접기

- 왼쪽 프로젝트 목록 위의 **«** 버튼으로 목록을 접고, **»**로 다시 편다. 접은 상태는 다음 실행 때도 유지된다.
- 접으면 새 프로젝트(+), 프로젝트 머리글자, Claude·Codex 상태 점, 설정(⚙), 사용법(?)만 남는다. 머리글자에 마우스를 올리면 이름과 폴더가 보인다.

*화면 설명: 왼쪽 목록을 접은 화면*
## 1단계 — 준비 상태 확인

*화면 설명: 첫 화면: 왼쪽 아래에 Claude CLI와 Codex 리뷰의 준비 상태가 표시된다*
- 왼쪽 아래 **Claude CLI**와 **Codex 리뷰**가 모두 초록이어야 실제로 실행할 수 있다.
- 이 앱은 모델을 포함하지 않는다. 설치된 Claude CLI와 Codex CLI를 실행하므로 인터넷과 로그인이 필요하다.
- 상태가 빨간색이면 원인을 누르고 안내를 따른다.
  - Claude: **터미널에서 로그인**(`claude auth login`)
  - Codex: 터미널에서 `codex login`
- 앱은 계정 정보와 토큰을 저장하지 않는다.

## 2단계 — 프로젝트 만들기

*화면 설명: 새 프로젝트 화면: 이름·목표를 쓰고 폴더는 Finder 창으로 고른다*
1. **+ 새 프로젝트**를 누른다.
2. 이름과 목표를 쓴다.
3. **폴더 선택…**을 눌러 Finder에서 작업할 폴더(저장소)를 고른다. 경로는 줄이지 않고 전체를 보여 준다. **경로 복사**로 복사할 수 있다.
4. **자동 수정 허용 경로**에서 Agent가 고쳐도 되는 하위 폴더를 고른다. 산출물 기본 위치도 수정 가능 영역에 들어간다.
5. 참고 문서와 기존 Claude 산출물은 직접 고른 파일만 연결된다.

*화면 설명: 기획 탭: 저장할 때마다 기획 버전이 올라가고 바뀐 항목이 이력에 남는다*
### 프로젝트 완성 문서(기획 탭)

이 프로젝트를 완성하려면 어떤 문서가 필요한지를 목록으로 관리한다. 아래쪽 저장 줄에 **검토 완료 n/m · 다음: (문서)**가 보이고, **완성 문서 목록…**을 누르면 팝업이 열린다.

*화면 설명: 완성 문서 목록: 순서·상태·경로, 만들기·검토 완료·빼기*
- 기본은 표준 8종이다: 개발 배경, R&D 사업 문서, 고객사 요구사항, 서비스 기획, 핵심·서브 기능, 화면 정의, 콘텐츠 설명, 추적표. 위에서부터 만드는 순서다.
- 상태는 실제 파일로 정한다.
  - **없음**: 그 경로에 파일이 없다.
  - **작성됨 · 검토 전**: 파일은 있지만 아직 검토 완료로 표시하지 않았다.
  - **검토 완료**: 사용자가 표시했다.
  - **검토 후 바뀜**: 검토 완료 뒤에 파일 내용이 바뀌었다.
  - **이 프로젝트에 불필요**: 뺀 문서다.
- 문서는 각자 환경에서 만들어 올린다.
  1. **프롬프트 복사**로 그 문서를 만드는 프롬프트(결과 경로 반영)를 복사해, 자신의 Claude·GPT 등에서 상황에 맞게 고쳐 문서를 만든다.
  2. **파일 올리기**로 만든 파일을 고르면 프로젝트 폴더의 문서 경로로 복사된다(Markdown·텍스트·PDF·CSV·JSON, 20MB 이하). 확장자가 다르면 경로의 확장자를 올린 파일에 맞춘다. 이미 있으면 덮어쓸지 묻는다.
  3. 경로를 눌러 열어 확인하고, 괜찮으면 **검토 완료**를 누른다. 앱이 자동으로 검토 완료 처리하지 않는다.
- 8개가 모두 있어야 하는 것은 아니다. 운영에서 지시하면 오퍼레이터가 등록된 문서를 근거로 읽고, 이번 지시에 필요한 근거가 빈약하거나 애매하면 채울 부분을 알려 주고 멈춘다(5단계 참고).
- 앞 순서 문서가 아직 없으면 "먼저 있으면 좋은 문서"로 알려 준다.
- 프로젝트에 맞게 조정한다: **빼기/다시 포함**, **↑↓**로 순서 바꾸기, **경로 바꾸기**(이미 있는 문서를 연결할 때), **+ 문서 추가**(이름·경로·지시문). **표준 세트로 되돌리기**는 목록만 되돌리고 파일은 그대로 둔다.
- **프롬프트 보기**에서 프롬프트 전체를 보고 복사할 수 있다. 경로를 바꾸면 프롬프트의 결과 경로도 그 경로로 바뀐다.

## 3단계 — 직원(Agent) 구성

*화면 설명: 기본 템플릿 불러오기: 소프트웨어 개발팀 표준(11명)과 범용 소규모 팀(7명) 중 고른다*
- **기본 템플릿 불러오기…**를 누르고 팀 구성을 고른다. 추가, 복제, 수정, 비활성화할 수 있다.
  - **소프트웨어 개발팀 표준(11명)**: 00 총괄, 01 기획·요구 분석, 02 설계, 03 백엔드 개발, 04 프런트엔드 개발, 05 데이터·DB, 06 문서 작성, 07 보안·권한 검토, 08 코드 리뷰, 09 시험·품질, 10 통합·결과물
  - **범용 소규모 팀(7명)**: 00 총괄, 01 조사·분석, 02 기획·설계, 03 작성·구현, 04 검증·시험, 05 독립 검토, 06 통합·결과물. 코드·문서·기획 어디에나 쓴다.
*화면 설명: 불러온 직원: 업무지시가 [역할]·[맡는 일]·[하지 않는 일] 틀로 들어 있다*

- 템플릿 직원의 업무지시는 같은 틀로 되어 있다.
  - **[역할]** 그 직원이 무엇을 맡는지 한 문장
  - **[맡는 일]** 순서대로 할 일
  - **[하지 않는 일]** 그 역할에서 금지하는 일
  - **[공통 규칙]** 수정 범위 밖 변경 금지, 실행하지 않은 검사를 통과로 쓰지 않기, 비밀값·고객 원문 금지, 외부 발송·배포 금지
  - **[보고 형식]** 수행 내용 / 변경 파일 / 검증 / 남은 문제 / 결정 필요
- 읽기 전용 검토자: 개발팀 표준의 07 보안·권한 검토·08 코드 리뷰, 범용 팀의 05 독립 검토. 허용된 시험 명령을 실행할 수 있는 직원: 개발팀 표준의 09·10, 범용 팀의 04·06.
- 불러올 때 직원마다 기본 검토 담당(작성자와 다른 직원)이 정해진다.
- 같은 코드의 직원이 이미 있으면 그 직원은 건너뛴다. 다른 세트를 이어서 불러오면 없는 코드만 추가된다.
- 직원마다 다음을 정한다.
  - 도구, 작업 폴더, Bash 허용 명령
  - 독립 검토 담당
  - 시간 제한, 재시도
  - 사용량 한도
- **00 총괄**은 운영 루프의 오퍼레이터 역할을 한다.
- **휴가 보내기 / 휴가에서 복귀**: 휴가 중인 직원은 업무에 배정되지 않는다. 정보는 그대로 남는다.
- **해고(삭제)**: 직원 목록과 업무 배정에서 뺀다. 되돌릴 수 없다.
  - 지난 실행·검토 기록은 남고, 기록 화면에는 이름 뒤에 "(해고)"로 표시된다.
  - 이 직원을 검토 담당으로 둔 직원은 검토 담당이 비워진다. 비워진 직원 이름을 알려 준다.
  - 지금 일하는 직원과, 작동 중인 미션의 00 총괄은 해고할 수 없다. 작업이 끝나거나 미션을 중단한 뒤 한다.
  - 해고한 직원이 담당인 업무 흐름은 저장할 때 오류로 표시된다.

### 사무실 — 직원 현황을 도트 그림 지도로 보기

**사무실** 탭은 직원들의 지금 상태를 위에서 본 사무실 지도로 보여 준다. 그림은 이 앱에서 새로 그린 도트 그림이다.

*화면 설명: 사무실: 00 총괄이 자기 책상에서 문서를 쓰고, 나머지 직원은 책상 옆에서 차례를 기다린다*
| 상태 | 위치와 모습 | 기준 |
|---|---|---|
| 일하는 중 — 코딩 | 자기 책상에 앉아 노트북, `</>` 말풍선 | 작성 작업의 산출물이 코드 등 문서가 아닌 파일 |
| 일하는 중 — 문서 작성 | 자기 책상에 앉아 종이에 연필, ✎ 말풍선 | 작성 작업의 산출물이 모두 문서(md·txt·html·pdf 등) |
| 일하는 중 — 계획·판단 | 클립보드를 들고 통로를 돌아다님 | 오퍼레이터(00)가 계획·판단 중 |
| 일하는 중 — 검토 | 회의실 탁자 오른쪽, 돋보기 | 독립 검토 담당으로 검토 중. Codex 리뷰 중이면 외부 검토자 **CX Codex**가 함께 앉는다 |
| 리뷰 받는 중 | 회의실 탁자 왼쪽, 땀방울과 `!?` 말풍선 | 자기 작업을 Codex·검토 담당·자동 검사가 확인하는 중 |
| 대기 중 | 자기 책상 옆에 서서 `...` | 진행 중인 미션이 있지만 지금 맡은 일이 없음 |
| 쉬는 중 | 휴게실 소파·커피 | 진행 중인 미션이 없음, 또는 사용 한도로 쉬는 중(다시 시작 시각 표시) |
| 휴가 중 | 아래 해변, 선글라스 | 휴가 보낸 직원 |

*화면 설명: 사무실: 00 총괄의 결과물을 Codex가 검토하고, 00 총괄은 회의실에서 리뷰를 받는다*
- 직원은 직군에 맞는 소품을 착용한다(이름이 우선, 없으면 역할로 판단). 총괄 넥타이, 기획·조사 안경, 설계 귀에 꽂은 연필, 백엔드·구현 헤드폰, 프런트엔드 비니, 데이터·DB 녹색 차양, 문서 베레모, 보안 경비 모자, 리뷰·검토 빨간 안경과 펜, 시험·검증 고글과 흰 가운, 통합 안전모. 머리·옷 색은 직원마다 정해진다.
- 지도 오른쪽 **직원별 상태** 목록에 직원마다 상태와 지금 하는 일이 한 줄로 나온다. 지도의 인물에 마우스를 올려도 볼 수 있다.
- 13인치 MacBook Air 기본 해상도(1470×956)에서 지도와 목록이 스크롤 없이 한 화면에 들어오도록 화면 크기에 맞춰 줄어든다.
- 실행 이벤트가 오면 바로, 그 밖에는 8초마다 다시 읽는다.
- 움직임 줄이기(손쉬운 사용) 설정을 켜면 움직임을 멈춘다.

## 4단계 — 운영: 지시하면 팀이 계속 일한다 (기본 사용 방식)

*화면 설명: 운영 탭: 왼쪽은 미션 목록, 가운데는 선택한 미션, 아래에 고정 입력창*
- 화면 아래 **입력창**이 Claude 대화창처럼 늘 고정돼 있고, 선택한 미션 상태에 따라 바뀐다.
  - **새 지시**(왼쪽 위 **+ 새 지시**): **지시하기**
  - **진행 중**: **추가 지시**(다음 사이클에 반영) · **지금 반영** · **중단**
  - **확인 대기**: **답변하고 계속** · **여기서 종료**(근거 문서 보완 요청이면 **보완했으니 다시 확인**)
  - **완료 보고**: **추가 지시하고 계속** · **여기서 종료**
  - **중단됨**: **이어서 다시 시작**

1. **운영** 탭 아래 입력창에 할 일을 문장으로 쓰고 **지시하기**를 누른다(⌘+Enter).
   - 필수 항목이 하나라도 비어 있으면 지시할 수 없다. 입력창 위와 새 지시 화면에 빠진 항목과 설정할 탭이 표시된다.
   - 필수 항목: 연결 폴더, **git 저장소 연결**(저장소 하나, 또는 바로 아래에 저장소가 있는 상위 폴더), 목표, 완료 조건, 자동 수정 허용 경로, 00 총괄, 작성·검토 직원 2명 이상, Claude CLI, Codex CLI.
   - **미션은 한 번에 하나만 작동한다.** 다른 미션이 작동 중이면 새 지시를 받지 않는다. 같은 프로젝트에 열려 있는 미션(확인 대기·완료 보고)이 있으면, 그 미션에 추가 지시하거나 종료한 뒤 새로 지시한다.
   - 프로젝트 완성에 필요한 문서는 **기획** 탭의 **완성 문서 목록…**에서 하나씩 만든다(아래 참고).
2. 앱이 아래 순서를 사이클 단위로 반복한다.
   - **오퍼레이터 계획:** 00 총괄이 계획하고 담당을 배정한다.
   - **담당 Agent 수행**
   - **Codex 리뷰:** 읽기 전용으로 리뷰한다.
   - **Claude 재검토:** 다른 직원이 Codex 지적을 원문과 대조한다.
   - **오퍼레이터 판단:** 다음 사이클로 계속할지 정한다.

*화면 설명: 진행 중: 위쪽 '오퍼레이터 루프'에 현재 단계(담당 Agent 수행)가 강조되고, 아래 '이번 사이클 작업 흐름'에 각 단계 상태가 실시간으로 표시된다*
- 위쪽 한 줄 **오퍼레이터 루프**는 지금 어느 단계인지 강조해 보여 준다. 왼쪽에 현재 사이클/상한이 있다. **루프 그림**을 누르면 반복·사용자 확인 흐름이 그려진 전체 그림을 펼친다.

*화면 설명: 지금 일하는 직원: 미션 화면*
*화면 설명: 직원 탭의 작업 중 표시*
- **결과물 파일**에는 이 미션이 만든 파일(직원 산출물, Codex 리뷰 보고서, 결과물 보고서)과 진행 기록에 나온 프로젝트 안 파일이 최신 사이클부터 나온다.

*화면 설명: 미션 화면: 한 줄 루프 표시, 결과물 파일(경로를 누르면 열림), 넓은 진행 기록*

- **중단**을 누르면 실행 중인 Claude·Codex 프로세스까지 실제로 멈춘다.

  - 이전 판단·답변·추가 지시와 스냅샷을 이어받는다. 바꿀 점이 있으면 카드에 적는다(선택).
  - 다른 미션이 작동 중이거나 같은 프로젝트에 열린 미션이 있으면 다시 시작하지 않는다.

*화면 설명: 중단된 미션: 아래 입력창의 '이어서 다시 시작'*
### 사용 한도(플랜 사용량)에 도달했을 때

- Claude나 Codex가 플랜 사용 한도에 걸리면 앱은 이를 **실패로 처리하지 않고** 멈춘다. 운영 탭에 **사용 한도 대기** 카드와 자동 재개 시각이 표시된다.
  - Claude가 알려 준 해제 시각에 1분을 더한 때에 자동으로 이어서 진행한다. 해제 시각을 알 수 없으면 30분 뒤에 다시 시도한다.
  - 한도 상태에서 재시도를 반복해 사용량을 더 쓰지 않는다. 끊긴 작성 작업은 해제 뒤 **같은 Claude 세션을 이어서** 작업한다.
  - 오퍼레이터 계획·판단 호출이 한도에 걸려도 같은 방식으로 기다렸다가 같은 호출을 다시 한다.
- 이미 한도가 풀렸다면 **지금 다시 시도**를 누른다. 아직 한도가 남아 있으면 다시 대기 상태로 돌아간다.
- 대기 중에도 **중단**과 **진행 중 추가 지시**를 쓸 수 있다. 중단하면 대기 중인 실행도 취소되어 다시 깨어나지 않는다.
- 대기 중에 앱을 끄면 다시 켤 때 미션은 사용자 확인으로 돌아가고 자동으로 재개되지 않는다.

*화면 설명: 사용 한도 대기: 자동 재개 시각과 '지금 다시 시도'*
*화면 설명: 진행 중: 아래 입력창에 추가 지시 · 지금 반영 · 중단*
- **진행 중 추가 지시**: 보다가 방향이 어긋나면 지시를 덧붙인다. 추가 지시는 오퍼레이터의 다음 계획에서 최우선으로 반영된다.
  - **추가 지시**: 지금 하는 작업은 마저 끝내고 다음 사이클 계획에 반영한다.
  - **지금 반영**: 진행 중인 Claude·Codex 작업을 멈추고 지시를 반영해 바로 다시 계획한다.

### git 커밋과 스냅샷·되돌리기

- **직원별 커밋**: 직원이 결과를 만들면 그 직원이 바꾼 파일만 직원 이름으로 커밋한다.
  - 작성자 예: `CREWGENAI 03 백엔드 개발`
  - Codex 리뷰 보고서는 `CREWGENAI Codex 리뷰`, 결과물 보고서는 `CREWGENAI 00 총괄(결과물 취합)` 이름으로 커밋한다.
  - 커밋 메시지 끝에 `Crewgenai-Mission / Cycle / Run / Node / Agent / Session`이 남아 누가 어떤 지시로 바꿨는지 추적할 수 있다.
  - 사용자가 작업 중인 다른 파일과 스테이징은 건드리지 않는다. push하지 않는다.
- **스냅샷**: 미션 시작 직전과 사이클이 끝날 때마다 git 태그(`crewgenai/m-<미션>/start`, `…/cycle-N`)를 남긴다.
*화면 설명: 스냅샷·되돌리기: 미션 시작 전·사이클 종료마다 남은 시점과 그 이후 CREWGENAI 커밋 수*
- **되돌리기**: 미션 화면의 **스냅샷·되돌리기**에서 시점을 고르면, 그 이후 이 미션이 만든 커밋만 `git revert`로 되돌린다.
  - 기록은 지우지 않으므로 되돌린 것도 다시 되돌릴 수 있다.
  - 충돌이 나면 아무것도 바꾸지 않고 알려 준다.
  - 미션이 작동 중이면 먼저 **중단**해야 한다.
- 설정의 **직원별 git 커밋·미션 스냅샷 사용**을 끄면 커밋·스냅샷을 하지 않는다(권장하지 않음).

### 여러 저장소를 한 프로젝트로 연결하기

- 연결 폴더로 여러 저장소를 담은 **상위 폴더**(예: `~/Documents/GitHub`)를 고를 수 있다. 상위 폴더 자체에는 `git init`을 하지 않는다.
- 앱은 연결 폴더 **바로 아래**에 있는 git 저장소 폴더를 찾는다. 링크 폴더, 숨김 폴더, 더 깊은 곳의 저장소는 대상이 아니다.
- **자동 수정 허용 경로**는 저장소 이름부터 적는다. 예: `jodalCrew/src`, `member-auth-backend/src/main`
- **직원별 커밋**: 직원이 바꾼 파일을 저장소별로 나눠, 각 저장소에 직원 이름으로 따로 커밋한다.
  - 실행 탭의 커밋 표시는 `저장소@커밋` 형식이다.
  - 저장소 밖 파일(상위 폴더의 결과물 보고서 등)과 커밋이 하나도 없는 저장소는 자동 커밋하지 않고 이유를 남긴다.
- **스냅샷**: 미션 시작 전과 사이클 종료마다 저장소별 현재 커밋을 앱 기록에 남긴다. 건드리지 않는 저장소가 많아도 태그를 늘리지 않도록 git 태그는 만들지 않는다.
- **되돌리기**: 이 미션이 커밋한 저장소마다 따로 `git revert`한다. 한 저장소에서 충돌이 나면 그 저장소는 되돌리기 전 상태로 두고, 이미 되돌린 저장소를 함께 알려 준다.
- Bash를 쓰는 직원의 복사본 실행은 수정 허용 경로가 속한 저장소만 복사한다.
- Claude 앱이 만드는 작업 트리 사본(`.claude/worktrees`)은 변경 비교·복사 대상에서 뺀다.

### 권한 때문에 멈췄을 때

- 직원의 권한은 앱 설정으로만 바뀐다. 지시문에 "권한을 줬다"고 써도 바뀌지 않는다.
  - 실행할 수 있는 명령: 직원 탭의 **허용 명령**. 적힌 접두어로 시작하는 명령만 실행된다.
  - 읽을 수 있는 프로젝트 밖 파일: 기획 탭의 **참고 문서**(읽기 전용)
- 작업이 권한 거부로 실패하거나, 지난 사이클과 같은 거부가 반복되면 오퍼레이터는 같은 설정으로 다시 돌지 않고 멈춘다.
- 멈춘 화면에 거부된 명령·경로가 나온다.
  - 명령: 접두어(예: `shasum -a 256`)를 확인·수정한 뒤 **허용 명령에 추가**를 누른다. Bash 도구가 꺼져 있던 직원은 함께 켜진다.
    - Windows판은 Bash를 쓰지 않으므로 명령은 검사 단계로 실행하거나 직접 실행한다.
  - 경로: **참고 문서에 추가**를 누르면 직원이 읽을 수 있게 열린다(쓰기는 안 됨).
- 허용한 뒤 아래 입력창의 **허용했으니 다시 시도**를 누른다. 허용하지 않을 거면 바꿀 지시를 적어 계속하거나 종료한다.
- 브라우저 실행·외부 접속처럼 직원의 격리 공간 밖이 필요한 일은 허용 명령에 넣어도 성공을 장담할 수 없다. 직접 실행하고 결과를 지시로 넘긴다.
- 폴더를 산출물로 정하면, 그 폴더 안에 정한 형식(예: 이미지) 파일이 하나 이상 있어야 통과한다.

### 화면 구역 접기·펴기

- 운영 화면의 **지시**, **결과물 파일**, **진행 기록**, **이번 사이클 작업 흐름**은 제목 줄을 누르면 접히고 다시 누르면 펴진다.
- 접힌 구역은 제목 옆에 개수(결과물 파일·진행 기록)나 지시의 첫 줄을 보여 준다.
- 접은 상태는 이 컴퓨터에 저장되어 다음에 열 때도 유지된다.

## 5단계 — 질문에 답하거나 완료를 검토한다

*화면 설명: 오퍼레이터가 확인을 요청한 상태: 질문에 답하고 '답변하고 계속'을 누르면 다음 계획으로 이어진다*
오퍼레이터가 사용자에게 묻는 때는 다음뿐이다. 그 밖에는 멈추지 않고 진행한다.
- 근거 문서가 빈약하거나 애매함(아래)
- 작업 완료
- 검토·결정 필요
- 추가 정보 필요
- 사이클 상한(설정, 기본 5) 도달
- 오류

### 근거 문서 보완 요청

*화면 설명: 근거 문서 보완 요청: 문서별로 부족한 부분과 채울 내용*
- 오퍼레이터는 계획 전에 기획의 완성 문서를 근거로 읽는다. 이번 지시에 필요한 근거가 빈약하거나(내용 없음·모순·미결정·범위 불명확) 애매하면 작업을 배정하지 않고, 문서별로 **무엇이 부족한지**와 **채울 내용**을 보여 주고 멈춘다.
- 문서를 보완해 **완성 문서 목록**에서 다시 올린 뒤 **보완했으니 다시 확인**을 누른다. 문서 대신 입력창에 내용을 직접 적어도 된다.

*화면 설명: 완료 보고: 결과를 검토하고 추가 지시를 하거나 '여기서 종료'를 누른다*
- **추가 지시하고 계속:** 다음 사이클이 이어서 돈다.
- **여기서 종료:** 미션을 닫는다.

## 6단계 — 단계별 상세 보기(실행 탭)

*화면 설명: 실행 탭: 사이클 흐름에서 'Claude 재검토' 단계를 눌러 방문 2회(1회차 수정 요청 → 2회차 승인)와 각 시도의 결과를 확인하는 화면*
- 운영 탭의 **실행 화면에서 자세히**를 누르면 그 사이클의 실행이 열린다.
- 단계마다 다음을 볼 수 있다. 각 시도의 상세 로그는 펼쳐서 본다.
  - 지시, 담당, 상태, 방문 횟수
  - 시도 이력(작성, Claude 검토, Codex 리뷰, 검사)
  - 변경 파일, 산출물, 실패 원인

## 7단계 — 직접 짠 흐름으로 실행하고 팀장 검토하기(선택)

*화면 설명: 업무 흐름 탭: 노드를 추가·연결해 순서를 정한다. 연결선이 실제 실행 순서다*
- **업무 흐름** 탭에서 직접 흐름을 만들 수 있다. 노드 종류는 기획·입력, Agent 작업, 명령 기반 검사, 독립 교차검토, Codex 리뷰, 조건 분기, 결과물 취합, 사용자 검토다.
  - 빨간 점선(실패 시)은 재작업할 담당으로 돌아가는 선이다.
  - 카드가 겹치면 **자동 정렬**을 누른다. 겹친 채 저장된 흐름은 열 때 자동으로 정렬해서 보여 준다.
  - **검사**를 누르면 끊긴 단계, 없는 담당, 출력 계약 누락, 잘못된 분기, 무한 순환, 동시 수정 충돌을 찾는다. 오류가 있으면 저장되지 않는다.
- 운영 루프가 사이클마다 만드는 흐름은 기록에만 남는다. 여기서 편집하는 흐름을 덮어쓰지 않는다.
- **실행** 탭의 **전체 업무 시작**으로 실행한다.

*화면 설명: 결과물·검토 탭: 하나로 묶인 결과물을 보고 수정 요청·보류·검토 완료 중 하나를 고른다*
- 결과물에는 다음이 한곳에 모인다.
  - 목표 대비 결과, 사용법
  - 변경, 검증 근거
  - 실패·미검증, 결정 필요 사항
- 팀장 결정은 그 시점의 결과물 해시에 묶인다. 파일이 바뀌면 이전 결정은 적용되지 않는다.

## 8단계 — 설정

*화면 설명: 설정: 실행 엔진(실제 Claude / 모의), 동시 실행 한도, Codex 리뷰 모델·강도, 운영 루프 사이클 상한*
- **실행 엔진:** 실제로 쓸 때는 **실제 Claude CLI**를 고른다. 모의 실행은 시험용이다.
- **동시 실행 한도:** 등록된 직원 수와 별개다.
- **Codex 리뷰 모델·강도:** 기본 `gpt-6.1-sol`, `high`.
- **사이클 상한:** 상한에 닿으면 계속할지 묻는다.

## 알아 둘 규칙

- **완료 판정:** 아래를 모두 만족해야 완료다. "완료"라는 문장이나 프로세스 종료만으로는 완료가 아니다.
  - 종료 코드 0과 `is_error=false`
  - 필수 산출물이 있고 형식이 맞음
  - 수정 범위 밖 변경 없음
  - 검사 통과
  - 독립 검토 승인
- **권한:** Claude CLI를 `--restricted`, `--permission-mode dontAsk`로 실행한다.
  - 파일 편집은 허용 경로만 할 수 있다.
  - Bash를 쓰는 직원은 프로젝트 복사본에서 실행하고, 범위 안 변경만 반영한다.
  - 검토자와 Codex는 읽기 전용이다.
  - 오퍼레이터가 계획한 검사 명령은 담당의 허용 명령이나 grep/test만 실행한다.
- **사용량:** claude.ai 구독으로 로그인했으면 화면의 $ 값은 **플랜 사용량의 API 환산 추정치**이고 청구가 아니다. 계정에 초과 사용분 결제(extra usage)를 켜 두었다면 플랜 한도를 넘는 부분은 청구될 수 있다.
- **종료·복구:**
  - 실행 중에 앱을 끄면 앱이 시작한 프로세스를 정리하고 "재개 확인 필요"로 남긴다.
  - 다시 열면 단계마다 재개 방법을 고른다: 새 시도 / 세션 이어서 / 산출물만 확인. 완료된 단계는 다시 실행하지 않는다.
  - 진행 중이던 미션은 저절로 다시 돌지 않고 사용자 확인을 기다린다.
- **데이터 위치:**
  - 기록: `~/Library/Application Support/CREWGENAI 개발팀 관리/workspace.db`(메뉴 **파일 → 데이터 폴더 Finder에서 보기**)
  - 결과물: 각 프로젝트의 산출물 위치
