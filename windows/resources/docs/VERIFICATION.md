## 실제 미션으로 보는 검증 (실제 Claude + 실제 Codex)

조달크루 문서 저장소에서 실제로 진행한 운영 미션의 화면이다(앱 데이터 사본에서 캡처, 원본 기록은 바꾸지 않음).

**① 지시 → 완료 보고까지 한 사이클**

*화면 설명: 실제 미션: 오퍼레이터가 계획한 작업 2개가 담당 수행 → Codex 리뷰 → Claude 재검토를 거쳐 '완료 보고'에 도달했다*

- **지시:** 작업 단위 진행 현황표와 원문 간 불일치 표를 근거와 함께 만들라.
- **계획:** 오퍼레이터(00 총괄)가 작업 2개로 나눠 15·01 담당에게 배정했다.
- **결과:** 9.7분 만에 완료 보고에 도달했다. 플랜 사용량은 API 환산 약 $4.58이다(청구 아님).

**② 이번 사이클 작업 흐름과 진행 기록**

*화면 설명: 사이클 작업 흐름(두 작업이 병렬로 진행)과 진행 기록(오퍼레이터 계획 원문)*

**③ Codex 리뷰 단계 — 실제 지적과 재검토 후 승인**

*화면 설명: Codex 리뷰 단계: 1회차는 '기준 커밋 설명이 사실과 다름'을 지적했고, 재작업 후 2회차에서 승인했다*

**④ Claude 재검토 단계 — Codex 지적을 근거로 기각**

*화면 설명: Claude 재검토: 불일치 표에 대한 Codex 지적(54줄)을 원문과 대조해 '불일치 표가 아니라 확인 표의 행'이라는 근거로 기각하고 승인했다*

이 미션에서 확인한 것:
- Codex 지적은 판정이 아니라 Claude 재검토의 입력으로 쓰였다. 타당한 지적은 재작업으로 이어졌고, 근거가 없는 지적은 기각됐다.
- 재작업한 담당만 다시 실행됐고, 나머지 단계는 다시 실행되지 않았다.

검토 중 발견한 제한: 두 작업을 병렬로 진행하면서 서로의 산출물을 확인하지 않았다. 현황표에 "conflicts.md는 만들지 않았다"는 서술이 남았다. 산출물 간 일관성 검사를 오퍼레이터 판단에 추가하는 것이 다음 작업이다.

자동 시험: `npm test` → 68개 통과(실제 git 저장소로 직원별 커밋·스냅샷·되돌리기·충돌 처리 포함), 0개 실패(Codex 리뷰 지적·실제 시나리오 결함 회귀 시험·운영 루프 시험 33개 포함).

실제 시나리오 시험(`npm run verify:real-scenarios`)의 첫 실행에서 결함 1건을 찾았다. 병렬 작업 중 먼저 끝난 작업의 정상 변경을, 늦게 끝난 작업의 범위 밖 변경으로 오인했다. 이 결함을 고친 뒤 재실행해 통과했다. CLI가 보고한 비용 추정치는 시나리오 1에 $0.080였다. 타입 검사: `tsc --noEmit` 통과.

## 미검증·제한

- 실제 Claude로는 별도 시험 프로젝트의 작은 문서 작업(작성·검토·재작업·병렬·취소)만 확인했다. 실제 업무 저장소에서의 작업 품질과 앱 비정상 종료 후 실제 세션 재개는 확인하지 않았다(재개는 모의 CLI로 확인).
- 서명·공증을 하지 않은 로컬 검증용 빌드다(ad-hoc 서명). 다른 Mac에 내려받아 열면 Gatekeeper가 막을 수 있다. 외부 배포에는 Apple Developer ID 서명·공증이 필요하다.
- arm64·macOS 27.0.1에서만 확인했다. Intel이나 다른 macOS 버전은 확인하지 않았다.
- 비용은 CLI가 보고한 추정치만 표시한다. 모의 실행은 비용을 보고하지 않으므로 "미보고"로 표시한다.
- Bash를 쓰는 작성자는 프로젝트 복사본(.git 제외, node_modules는 원본 링크)에서 실행되고, 범위 안 변경만 반영한다. 복사본 안의 git 명령은 동작하지 않는다. 모노레포 workspace 링크는 원본 코드를 가리킬 수 있으므로, 반영 뒤 실제 프로젝트에서 도는 검사 노드를 완료 기준으로 둔다.
- 실제 문서 저장소 시범(조달크루 문서 5개)은 직원별 비용 한도 $0.5를 넘어 CLI가 중단했고, 완료로 판정하지 않았다(`error_max_budget_usd`). 한도 기본값은 사용자 결정 사항이다.
- 범위 밖 변경이 탐지돼도 자동으로 되돌리지 않는다. 사용자 파일 보존을 위해서다.
