# 핵심 기능·서브 기능 명세서

> 요약: 요구사항과 서비스 기획을 기능 트리로 나누고, 기능별 입력·처리·출력, 예외, 권한, 수용 기준, 우선순위를 정의한 명세서를 만든다.
> 산출물: crewgenai-output/docs/05-features-core-sub.md

## 언제 쓰나

- 서비스 기획서(04)를 개발 가능한 단위로 쪼갤 때
- 개발·테스트 담당이 같은 기능 정의를 보고 작업해야 할 때
- 화면 정의서(06)에서 연결할 기능 ID가 필요할 때
- 기능별 권한·예외 처리를 빠짐없이 정해야 할 때

## 문서 구성(산출물 목차)

1. 문서 정보 — 제품명, 작성일, 버전, 참고 문서(03·04) 버전
2. 기능 트리 — 들여쓰기 목록: `FN-001 핵심 기능명` 아래 `FN-001-1 서브 기능명`
3. 기능 목록 요약 — 표: `FN ID | 기능명 | 상위 FN | 관련 REQ | 우선순위(필수/중요/선택) | 상태(확정/초안/제안)`
4. 기능 상세 — 기능별 하위 절, 다음 항목 포함
   - 목적, 관련 REQ, 관련 시나리오
   - 입력 표: `항목 | 형식 | 필수 | 검증 규칙 | 출처`
   - 처리 규칙(번호 목록)
   - 출력 표: `항목 | 형식 | 저장 위치 | 노출 대상`
   - 예외 표: `예외 조건 | 처리 | 사용자 안내(CT-xxx) | 기록 여부`
   - 권한 표: `역할 | 허용 동작 | 거부 시 처리 | 집행 위치`
   - 수용 기준 표: `번호 | 조건 | 기대 결과`
5. 공통 규칙 — 인증, 조직별 권한 확인, 승인 집행, 실행 기록, 오류 처리 등 여러 FN에 공통인 규칙
6. 요구 반영 대조 — 표: `REQ ID | 연결 FN | 반영 상태(반영/부분/미반영) | 미반영 사유`
7. 근거 목록 — 표: `번호 | 파일경로:줄번호 | 내용 요약`
8. 사용자 결정 필요 항목 — 표: `번호 | 결정할 내용 | 선택지 | 영향 | 결정 기한`
9. 확인 필요 항목 — 표: `번호 | 확인할 내용 | 확인 방법 | 관련 FN`

## 작성 규칙

- 근거: 기능마다 관련 `REQ-xxx`를, 세부 규칙마다 `(파일경로:줄번호)` 또는 "확인 필요"를 단다.
- ID 체계: 핵심 `FN-001`, 서브 `FN-001-1`. 한 번 붙인 ID는 삭제 시에도 재사용하지 않고 "폐기"로 표시한다.
- 사용자 안내 문구는 직접 쓰지 않고 07 콘텐츠 설명서의 `CT-xxx`로 참조한다. 아직 없으면 "CT 후보"로 적는다.
- 수용 기준은 "조건 → 기대 결과" 형식으로, 08 추적표의 `TC-xxx`로 바로 옮길 수 있게 쓴다.
- 숫자 단위: 길이 제한은 글자 수, 파일 크기는 MB, 시간 제한은 초로 쓰고 근거를 단다.
- 권한: 역할명은 04 문서의 운영 정책과 같은 이름을 쓴다. 집행 위치는 `서버`/`DB`/`외부 시스템` 중 하나다.
