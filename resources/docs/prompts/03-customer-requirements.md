# 고객사 요구사항 정의서

> 요약: 고객사 자료에서 요구사항을 추출해 요구 ID·출처·우선순위·수용 기준을 붙이고, 기능/비기능과 미확정·충돌 요구를 분리한 정의서를 만든다.
> 산출물: crewgenai-output/docs/03-customer-requirements.md

## 언제 쓰나

- 고객 인터뷰·회의록·RFP·이메일을 받은 뒤 요구를 한 곳에 정리할 때
- 서비스 기획(04)과 기능 명세(05) 전에 무엇을 만들지 합의 기준을 세울 때
- 요구가 여러 자료에 흩어져 있어 중복·충돌을 찾아야 할 때
- 고객 검토 회의 전에 확인 질문 목록을 준비할 때

## 운영 탭에 붙여넣을 지시문

```text
목표: {{고객사}}의 {{제품명}} 요구사항 정의서를 작성한다. 결과는 crewgenai-output/docs/03-customer-requirements.md 한 파일이다.
읽을 자료: {{참고 자료 경로}}(회의록, RFP, 이메일 요약 등), crewgenai-output/docs/01-why-develop.md(있으면). 이 경로 밖의 자료는 인용하지 않는다.

필수 섹션(이 순서): 1 문서 정보, 2 범위와 이해관계자, 3 요구 수집 출처, 4 기능 요구, 5 비기능 요구, 6 제약 조건, 7 미확정 요구, 8 충돌 요구, 9 근거 목록, 10 사용자 결정 필요 항목, 11 확인 필요 항목.

- 각 요구에 출처(파일경로:줄번호), 요청자 역할, 우선순위(필수/중요/선택), 수용 기준(검증 가능한 조건)을 적는다.
- 출처 없는 요구를 만들지 않는다. 작성자가 추론한 요구는 "(추론)"으로 표시하고 7절에 둔다.
- 서로 모순되는 요구는 4·5절에서 빼고 8절에 양쪽 출처와 함께 둔다.
- 고객 원문은 그대로 복사하지 않고 요지만 쓴다. 개인정보·비밀값은 제외한다.
- 고객사명, 수치, 일정을 지어내지 않는다.
완료 기준:
- 11개 섹션이 모두 있다. 모든 REQ에 출처·우선순위·수용 기준이 있다.
- 수용 기준이 "잘", "빠르게" 같은 모호한 표현 없이 측정·확인 가능하다.
- 7·8절 항목마다 확인 질문이 있다.
결과 파일 경로, REQ 수(기능/비기능), 미확정·충돌 수를 마지막 보고에 적는다.
```

## 문서 구성(산출물 목차)

1. 문서 정보 — 고객사(익명 가능), 제품명, 작성일, 버전, 참고 자료 경로
2. 범위와 이해관계자 — 대상 업무 범위, 표: `이해관계자 | 역할 | 관심사 | 의사결정 권한`
3. 요구 수집 출처 — 표: `출처 ID | 자료 종류 | 파일경로 | 일자 | 비고`
4. 기능 요구 — 표: `REQ ID | 요구 내용 | 요청자 역할 | 우선순위 | 수용 기준 | 출처 | 상태`
5. 비기능 요구 — 표: `REQ ID | 분류(성능/보안/가용성/사용성/규정 등) | 요구 내용 | 우선순위 | 수용 기준 | 출처 | 상태`
6. 제약 조건 — 표: `번호 | 제약(기술·일정·예산·규정) | 영향 | 출처`
7. 미확정 요구 — 표: `REQ ID | 내용 | 미확정 사유 | 확인 질문 | 확인 대상`
8. 충돌 요구 — 표: `충돌 ID | 관련 REQ | 내용 A(출처) | 내용 B(출처) | 영향 | 확인 질문`
9. 근거 목록 — 표: `번호 | 파일경로:줄번호 | 내용 요약`
10. 사용자 결정 필요 항목 — 표: `번호 | 결정할 내용 | 선택지 | 영향 | 결정 기한`
11. 확인 필요 항목 — 표: `번호 | 확인할 내용 | 확인 방법 | 관련 REQ`

## 작성 규칙

- 근거: 모든 REQ에 `(파일경로:줄번호)`를 단다. 여러 출처가 있으면 모두 적는다.
- 상태 값: `확정`(고객 확인 출처 있음), `초안`(자료에서 추출, 고객 미확인), `미확정`, `충돌` 중 하나만 쓴다.
- 우선순위: `필수`/`중요`/`선택` 세 단계만 쓰고, 근거가 없으면 "확인 필요"로 둔다.
- 수용 기준: 주어·조건·기대 결과가 있는 검증 가능한 문장으로 쓴다(예: "권한 없는 사용자가 승인 버튼을 누르면 403 응답과 안내 문구를 표시한다").
- 숫자 단위: 응답 시간은 초/밀리초와 측정 조건, 용량은 건수·바이트 단위를 함께 적는다.
- ID 연결: `REQ-001`은 05 기능 명세의 `FN-001`, 08 추적표에서 그대로 인용한다. 01 문서의 `PRB-xxx`가 있으면 관련 문제로 연결한다.
- 고객 원문·개인정보·비밀값은 옮기지 않는다.

## 검토 기준(Codex·Claude 재검토용 체크리스트)

- [ ] REQ ID가 중복·누락 없이 순번으로 붙어 있다.
- [ ] 모든 REQ에 출처, 우선순위, 수용 기준, 상태가 있다.
- [ ] 수용 기준에 "잘", "빠르게", "편리하게" 같은 측정 불가 표현이 없다.
- [ ] 한 REQ에 둘 이상의 요구가 섞여 있지 않다.
- [ ] 출처 없는 요구가 4·5절에 없다(추론 요구는 7절에 있다).

- [ ] 인용한 `파일경로:줄번호`가 실제 내용과 일치한다.
- [ ] 고객 원문 그대로의 복사, 개인정보, 비밀값이 없다.
